# Request admission

Before dispatching a learning or planning command, HTTP and the exported runtime gateway evaluate the same registered admission formers under the same learner lock. A command that asks the tutor passes two formers, as described below; lessons, practice, and tutor answers in a session pass a third that explains deleted sources; and the two graded-work commands, Extract and Confirm, pass one more after their own, which recognizes a paper already imported from another upload. Every other command passes one. A declined result produces an immediate explanation. This avoids waiting for an endpoint whose conditions cannot hold. Identity always comes from the session; request fields cannot select another owner. Each endpoint repeats the ownership guard that admission checks first, and when that guard fails it answers a refusal of its own, so a caller that skips admission gets an answer instead of waiting for the request limit. Each concept still enforces its own state rules.

The adapter performs no domain writes and sequences no learning actions. The engine evaluates the formers. Native callers use the runtime's exported `gateway`; the raw assembled invoker bypasses this admission layer. On that path the endpoints answer these refusals themselves: Lesson and Task answer `SKILL_UNAVAILABLE` when the skill is not one of the learner's confirmed skills; Respond, Question, Reply, Hint, Transcript, and Assess answer `SESSION_UNAVAILABLE` when the session is not one of the learner's open sessions; FinishLesson answers `SESSION_UNAVAILABLE` when the session is not one of the learner's open lessons; ReopenLesson answers `SESSION_UNAVAILABLE` when the session is not one of the learner's finished lessons, or is archived; ArchiveConversation and RestoreConversation answer `SESSION_UNAVAILABLE` when the session is not one of the learner's own; RetryAssessment answers `SESSION_UNAVAILABLE` when the session is not one of the learner's own; Correct and Regrade answer `REVISION_CASE_UNAVAILABLE` when the case is not one of the learner's own; Suggest answers `MATERIAL_UNAVAILABLE` for a material that is not the learner's own, `COURSE_UNAVAILABLE` for the learner's material in a course they do not own, and `WORK_MATERIAL_NOT_SOURCE` for the learner's own work. The planning endpoints answer as the [planning flows](Planning.md) describe. Admission declines all of these first over HTTP, with the details below, so these answers matter for the host's own code paths, for tests that bypass admission, and for a route added later without an admission entry. Other conditions, such as a stale dialogue length, are still checked only by admission and the concepts. The [advisory review](../advisory-review.md) records the P2 decision to keep this boundary.

A command that asks the tutor first passes [TutorReady](former:Settings.TutorReady), before its own former. These are the commands at `/learning/lesson`, `/learning/task`, `/learning/question`, `/learning/reply`, `/learning/hint`, `/learning/assess`, `/learning/retry`, `/learning/regrade`, `/courses/skills/suggest`, and `/courses/graded/extract`. `/learning/lesson` saves the lesson without asking the tutor, but the page asks Reply for its opening explanation right after, so a saved choice that is no longer offered is refused before a lesson is saved that the tutor could not explain. TutorReady admits the command when the learner has no saved tutor choice, or has a saved choice that is still offered. A declined result explains: "The tutor model or thinking level you chose is no longer offered. Choose another one in the Tutor panel." The [tutor settings](Settings.md) describe the choice.

`/learning/correct` shares RegradeReady but makes no AI call, so it does not pass TutorReady.

## Deleted sources

Lessons and practice use the sources that remain after the learner deletes a material, as the [learning flows](Learning.md) describe. When none remains, the general checks below would decline with a sentence that does not say why, so two formers come between TutorReady and the command's own former and explain this case first:

- [SkillSourcesLeft](former:Access.SkillSourcesLeft) admits `/learning/lesson` and `/learning/task` unless [SkillSourcesDeleted](view:Reads.SkillSourcesDeleted) holds for the learner and the skill. Otherwise it declines with "Every material this skill was taught from has been deleted. Add another material from this course as a source under Manage skills, then try again."
- [SessionSourcesLeft](former:Access.SessionSourcesLeft) admits `/learning/question`, `/learning/reply`, and `/learning/hint` unless [SessionSourcesDeleted](view:Reads.SessionSourcesDeleted) holds for the learner and the session. Otherwise it declines with "The materials this session was grounded in have been deleted, so the tutor can no longer answer here. Your saved work stays, and you can still finish the lesson or submit the task."

Neither former holds back anything else. For a skill that is not one of the learner's confirmed skills, or a session that is not one of their open sessions, the view does not hold, so the former admits and the command's own former declines with its usual sentence; another learner's skill or session is never described. Respond, Transcript, FinishLesson, ReopenLesson, and Assess need no tutor source, so a learner can still answer an open task, finish an open lesson, and have the attempt graded, as the learning flows describe. ReopenLesson is admitted for a finished lesson whose every source was deleted, but the lesson page does not offer it then, because the tutor could not answer in the reopened lesson.

The endpoints check these two cases only in the stages that prepare a tutor request, which find no source and never reach the tutor. Their first guards are unchanged. A caller that skips admission therefore gets no answer before the request limit, as it does for a missing mastery track or prerequisite, and its first stage may already have saved something: Question saves the learner's question, and Hint records the request for help.

[DeleteReady](former:Access.DeleteReady) admits the host's delete route, as the [materials composition](Materials.md#deleting-a-material) describes. It holds when `Library._material` finds the material as the learner's own and [OwnedCourse](view:Courses.OwnedCourse) finds its course as the learner's. It declines alike for an unknown material, another learner's material, and a material already deleted; the route then answers a repeat of the learner's own deletion with success and the other two with the same refusal, so a learner cannot learn whether someone else's material exists.

[LessonReady](former:Access.LessonReady) checks the corresponding command against current owned state.
[TaskReady](former:Access.TaskReady) checks the corresponding command against current owned state.
[ResponseReady](former:Access.ResponseReady) requires an open session, the current dialogue length, and text or at least one attachment. Every attachment must be listed once and be the learner's own material in the session's course, one of their sources or their own work; otherwise the whole response is declined, with a detail that does not name the attachment.
[ReplyReady](former:Access.ReplyReady) admits Reply for an open lesson that waits for the tutor, which [lessonAwaitsTutor](computation:lessonAwaitsTutor) decides: the lesson is unexplained, or its latest turn is a learner question. Otherwise it declines with the sentence "Send a question in an open lesson before asking for a reply."
[HintReady](former:Access.HintReady) checks the corresponding command against current owned state.
[TranscriptReady](former:Access.TranscriptReady) checks the corresponding command against current owned state.
[FinishReady](former:Access.FinishReady) admits finishing a lesson when [OpenSession](view:Reads.OpenSession) holds and `GroundedTutoring._lesson` finds the session as a lesson, the same two conditions the FinishLesson endpoint states. It declines an unknown session, another learner's session, a closed session, an archived session, and an open practice task alike, with the sentence "Choose one of your open lessons. A practice task closes when you submit it for assessment."
[ReopenReady](former:Access.ReopenReady) admits continuing a finished lesson when [ReopenableLesson](view:Reads.ReopenableLesson) holds, the condition the ReopenLesson endpoint states: the session is the learner's own lesson, its status is CLOSED, and it is not archived. It declines an unknown session, another learner's session, a lesson that is still open, a practice task, open or submitted, and an archived lesson alike, with the sentence "Choose one of your finished lessons to continue. A practice task cannot be reopened, and an archived lesson must be restored first."
[ConversationReady](former:Access.ConversationReady) admits archiving and restoring a conversation when [OwnedSession](view:Reads.OwnedSession) holds, the same condition the ArchiveConversation and RestoreConversation endpoints state, so it admits an open or a closed conversation, a lesson or practice, archived or not. It declines an unknown session and another learner's session alike, with the sentence "Choose one of your own conversations to archive." at `/learning/archive` and "Choose one of your own conversations to restore." at `/learning/restore`. The [learning flows](Learning.md) explain why archiving accepts an open conversation.
[AssessmentReady](former:Access.AssessmentReady) checks the corresponding command against current owned state.
[RetryReady](former:Access.RetryReady) checks the corresponding command against current owned state.
[RegradeReady](former:Access.RegradeReady) admits Correct and Regrade for the learner's own practice or imported case ([OwnedAnyCase](view:Reads.OwnedAnyCase)) whose effective judgment is the one the learner saw. Regrade then refuses an imported case itself.
[AdjustReady](former:Access.AdjustReady) requires a confirmed skill that the learner owns. It declines an unknown skill, another learner's skill, and a draft skill with the same detail as the endpoint's `SKILL_UNAVAILABLE`, "Choose one of your confirmed skills before adjusting its estimate." It does not check the key, value, or reason, so the concept's message explains those refusals.
[SuggestionReady](former:Access.SuggestionReady) checks the corresponding command against current owned state. It admits only one of the learner's sources in a course they own; for the learner's own work, such as a photo attached to an answer, it declines with the same detail, "Choose a source from your own course."
[GradedReady](former:Access.GradedReady) admits Extract and Confirm only when [GradedMaterial](view:Importing.GradedMaterial) holds. Otherwise it declines, with the admission layer's usual code, and the sentence "Choose graded work that you imported into one of your courses." The answer is the same for an unknown material, another learner's material, a material outside the learner's courses, and the learner's own ungraded material.
[PaperNotImported](former:Access.PaperNotImported) comes after GradedReady for Extract and Confirm. It admits unless [PaperImported](view:Importing.PaperImported) holds, that is, unless the learner already imported this paper's marks from another upload of the same files in the course. When it declines, [EarlierImports](former:Importing.EarlierImports) names that upload, the way PracticePrerequisite names a prerequisite below, and the sentence gives its title and the date of the import; the [graded import](Importing.md#the-same-paper-uploaded-twice) states the sentences. Only admission reads PaperImported, so the endpoints do not answer this case themselves; Importing explains why, and how the paper-named source key covers a caller that skips admission.
[CourseReady](former:Access.CourseReady) checks the corresponding command against current owned state.
[PlanReady](former:Access.PlanReady) checks the corresponding command against current owned state.
[ItemReady](former:Access.ItemReady) checks the corresponding command against current owned state.
[BeginReady](former:Access.BeginReady) checks the corresponding command against current owned state.

[QuestionReady](former:Access.QuestionReady) requires an open lesson, current dialogue length, and valid learner content, with the same attachment rule as ResponseReady.

## Admission and the endpoints read the same conditions

Admission and the endpoints check the same conditions, and each condition is stated once. Each learning command endpoint has a refusal branch for its first guard, so the endpoint by itself answers every caller. Admission adds two things on top: a sentence that tells the learner what to do, and a stop before the endpoint starts work that cannot finish, such as saving a question when the dialogue the learner saw is out of date. Admission therefore does not replace the endpoint's checks, and the endpoint does not repeat admission's checks in a separate copy.

The shared conditions live in two places. The [shared reads](LearningReads.md) declare views, such as SessionSources and PendingGrade, that both sides read. The learning composition declares condition helpers that return a list of conditions: `learnerWork` admits learner work, and Respond, Question, ResponseReady, and QuestionReady all state it; `sessionTutorRequest` prepares the tutor request of Question, Reply, and Hint from the open session; `openingTutorRequest` prepares Reply's request for an unexplained lesson's opening explanation; `gradeRequest` prepares the grading request of Assess, RetryAssessment, and Regrade; and `afterTutor` states the two paths after the tutor answers, saving the answer when the skill or session is unchanged and answering `SKILL_CHANGED` or `SESSION_CHANGED` otherwise. ReplyReady reads SessionSources and RetryReady reads PendingGrade, the same views their endpoints read. A change to one of these conditions therefore changes admission and the endpoint together.

Some differences between admission and the endpoints are deliberate:

- AssessmentReady also checks the dialogue length and the attempt's content with `attemptIsReady`. The endpoint checks only the learner's review and declarations with `reviewApproved`, and `GroundedTutoring.confirmAttempt` checks the dialogue length itself.
- After the attempt is confirmed, the submitted case closes the session, so Assess grades through PendingGrade rather than OpenSession.
- HintReady requires `GroundedTutoring._task`. The endpoint's first stage checks only OpenSession, and the concept refuses a hint outside a practice task.
- QuestionReady and the Question endpoint require `GroundedTutoring._lesson`. The Reply endpoint has two cases, an unexplained lesson (`lessonUnexplained`) and an unanswered question (`hasLessonQuestion`), and ReplyReady requires `lessonAwaitsTutor`, which holds exactly when one of them does. The concept refuses a question in an unexplained lesson, so Question needs no condition of its own for it.
- The tutor choice is read in the stage that asks the tutor, which for Question and Hint comes after their first write. Admission checks the choice earlier, with TutorReady.
- Regrade answers `REGRADE_IMPORTED_UNAVAILABLE` for an imported case, which RegradeReady admits so that Correct can use it.
- Adjust and the planning endpoints keep their own inline details.

When [TaskReady](former:Access.TaskReady) declines, [PracticePrerequisite](former:Access.PracticePrerequisite) reads the same skill context and uses [prerequisiteToPractice](computation:prerequisiteToPractice) to look for a prerequisite that is not ready. If it finds one, the explanation names it: Work on “<title>” first. This skill builds on it. Otherwise the practice explanation stays: Set starting confidence and check the prerequisites before starting fresh practice.

```computations
prerequisiteToPractice(skills: SkillMapping.SkillMapRows, tracks: MasteryEstimating.ProgressRows, skill: SkillMapping.Skill) : PrerequisiteChoice
  Finds the prerequisite to work on first. It starts from the skill's direct prerequisites that are not ready by the rule prerequisitesReady uses. It follows prerequisites that are also not ready until it reaches one whose own prerequisites are all ready, taking the lowest skill identity at each step, and gives that skill's title. Answers found false when every direct prerequisite is ready.
```

Exam and tradeoff commands are admitted on course ownership alone, with the detail "Choose one of your own courses.", the same answer the planning endpoints give for a course that is not the learner's. The planning concept's own refusals then reach the learner with its messages. Begin admission uses the planning composition's StartAllowed view, so admission and the endpoint apply the same urgent-mode rule.
