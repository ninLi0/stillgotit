# The host

StillGotIt is built in three layers. The concepts own the records and the rules, the compositions in `src/compositions/` connect the concepts to each other and to the browser, and the host runs everything else. The host is the Bun server code in `src/main.ts`, `src/host/`, and `src/storage/`. It handles the work that is not any concept's job: reading the session cookie, talking to Google Gemini, keeping uploaded files, saving import progress, supplying the clock, and holding the locks that keep each learner's requests in order. It never decides a learning rule, it never sequences learning actions, and it never writes to a concept's collections. The [runtime contract](runtime.md) states these rules in full. This page names each part of the host, the file that implements it, what it owns, what it calls or serves, and the design page that describes it in detail.

## The pattern

The concepts own the records and the rules. Each concept keeps its own MongoDB collections and refuses any change that would break its rules: GroundedTutoring refuses a material with no readable content, for example, and StudyPlanning refuses to replace a plan while an activity is in progress. No concept calls another. The compositions connect them. Each endpoint, reaction, view, and former in `src/compositions/` says which action follows which and under what conditions, and the engine runs them, so every sequence of domain actions appears in the [generated read-back](../generated/stillgotit.md) as a when, where, then rule.

The host holds everything that needs the outside world. Cookies arrive with HTTP requests, files live in S3 or on disk, the tutor is a Google service that can be slow or refuse, time comes from a clock, and the single server process keeps order with locks. None of this fits inside a concept or a composition. Views and formers cannot read the host's stores, an engine flow has at most 90 seconds while transcribing a lecture takes longer, and file and provider work never runs inside a `where` condition. Each actor in the table therefore handles one piece of that outside work and prepares values for the concepts, but it leaves every decision about learning to the concepts and compositions. The tutor, for example, reaches the flows only as the function inside the `TutorGenerating.generate` action: it receives prepared sources, returns a checked answer, and can neither read nor write concept state. The host's own records, which are import progress, Files API references, and recovery keys, live in collections that no concept reads.

When host work must change concept state, it goes through the application's endpoints or the exported gateway, which check the session, admission, and each concept's own rules. The upload route, for example, saves a finished import through the private `/internal/materials/add` endpoint instead of writing to GroundedTutoring's collection, and native integrations use the exported gateway, which applies the same admission checks and locks as HTTP. The host reads concept state in a few places, always through a concept's own query or a registered former: admission evaluates the formers, and the sign-in continuation reads the Commons and registration queries named in the table. Two concept actions are called directly, and both concern sessions. The HTTP adapter calls `Sessioning.use` to learn which learner a request belongs to before it takes that learner's lock, which also records that the session was used. The sign-in continuation calls `Sessioning.end` to withdraw a session that was created after its sign-in attempt expired.
