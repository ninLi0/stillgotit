## Core user journey

A learner opens an empty StillGotIt app and signs in with Commons. They add MIT 18.06SC Linear Algebra and upload the lesson summary on matrix multiplication. The app proposes skills and demonstration requirements. The learner confirms them, selects matrix multiplication, and reports their confidence. They choose **Walk me through an example** and ask a follow-up question. They then solve two fresh problems without hints. They explain the method and results by voice, correct any transcription errors, and confirm their response before assessment. The app shows feedback and updates the skill's mastery estimate on the tree. The learner sets a daily time budget and receives a next review activity. After the app restarts, their course, work, mastery estimate, and review plan remain available.

## P2 scope

Support one course per learner. Use [MIT 18.06SC Linear Algebra, Fall 2011](https://ocw.mit.edu/courses/18-06sc-linear-algebra-fall-2011/pages/ax-b-and-the-four-subspaces/multiplication-and-inverse-matrices/) for the demonstration. Start with matrix multiplication. This unit includes a lesson summary, transcript, problems, and solutions. The course is an example; the app must accept other course materials.

Use Commons sign-in. The [current ConceptBox example](https://github.com/mit-sdg/conceptbox) provides the relevant components and documents local sign-in support. It uses sync-engine 1.1.0, the same version as this project. A real sign-in must still be tested.

Provide two ways to study: ask a free question, or choose a button such as **Explain this**, **Walk me through an example**, **Give me practice**, or **Check my understanding**. Both use the same course materials and skill context. Track help given during practice so it cannot count as an independent success.

Make voice the main way to answer. A learner can speak both their reasoning and result. Text and photos remain optional. Ordinary lessons need no transcript approval; learners can correct errors when needed. Before grading, show the whole attempt for one transcript review, especially for numbers and mathematical terms. Keep microphone audio only while transcription needs it, then delete it. Uploaded lecture recordings remain course material.

### File import

Broad material support is part of P2. PDF import is no longer deferred. Use the following families as the initial test list. Support for every file that Codex or ChatGPT can process remains a goal to verify, not a completed feature.

| Material | Planned handling |
| --- | --- |
| PDFs, including scans | Read text and page images. Keep page references. |
| Documents and slides, including Word and PowerPoint | Read text. Render pages or slides when diagrams and equations are needed. |
| Spreadsheets, including Excel, CSV, and TSV | Read the relevant sheets and cells. Preserve row and column context. |
| Text, Markdown, source code, and notebooks | Read text and code. Preserve section or cell references. |
| Images and photos | Read the image and allow the learner to correct unclear content. |
| Audio recordings | Transcribe speech and let the learner check it. |
| ZIP archives of course materials | Extract supported contents with file-count and expanded-size limits. |

An accepted upload is not enough. Test whether the tutor can use its text, equations, tables, and diagrams. Keep the original file and show which content was read. Report unreadable or unsupported content instead of silently omitting it.

The [OpenAI file-input guide](https://developers.openai.com/api/docs/guides/file-inputs) documents direct inputs for common documents, slides, spreadsheets, and text. Non-PDF documents supply text only, so diagrams need rendering. Direct spreadsheet input covers up to 1,000 rows per sheet; larger sheets need a separate reading path. Direct file requests have a combined 50 MB limit, with each file under 50 MB. These are provider limits, not proof that our importer handles each format.

[Image inputs](https://developers.openai.com/api/docs/guides/images-vision) and [audio transcription](https://developers.openai.com/api/docs/guides/speech-to-text) use separate paths. Transcription accepts recordings up to 25 MB per request. Larger inputs need splitting or a clear size error. Archive extraction, document rendering, and notebook parsing also require their own implementation and tests.

### Learning behavior

The model explains material, proposes skills, creates practice, and proposes assessments. The app stores the confirmed skills, source references, attempts, help received, judgments, mastery estimates, and review plan. Changes must pass the relevant concept actions. A chat response alone must not change a mastery score.

The proposed P3 work includes graded coursework calibration, full exam tradeoff planning, broader skill-map interactions, and visual polish. The full P1 design remains the target for the finished project.
