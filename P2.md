## Core user journey

A learner opens an empty StillGotIt app and signs in with Commons. They add MIT 18.06SC Linear Algebra and connect their ChatGPT plan. They upload a lesson on matrix multiplication, review the proposed skills, and confirm the requirements. They report their confidence, choose a worked example, and ask a follow-up question. They then solve two fresh problems and explain the method and results by voice. They review the transcript before assessment. The app saves feedback and updates estimated mastery on the skill tree. The learner sets a daily time budget and receives a next review activity. Their course, source files, work, judgments, estimate, and plan remain available after restart.

## Implemented

| Area | Current behavior |
| --- | --- |
| Accounts | Commons sign-in, saved local identity, session, and one course per learner. |
| AI connection | OpenAI's public OAuth flow for local/open-source apps. ChatGPT plan usage is separate from Commons identity. Account, model, and reasoning effort selection are scoped to the learner. |
| Import | PDF text and page images; document and slide text/rendering; spreadsheet cells; text/code/notebooks; images; audio transcripts; bounded ZIP contents. Originals and reading limitations remain inspectable. |
| Skill map | A dedicated Home view with one leaf per skill, selected-skill details, and a study plan. Import and skill review have a separate setup view. |
| Learning | A dedicated chat with conversation history, free requests, preset prompts, grounded lessons, follow-up questions, fresh checks, and recorded hints. |
| Answers | One composer for voice transcription, text, photos, and reasoning effort. The student reviews the whole attempt before assessment. |
| Assessment | Saved original work, explained judgments, regrades, manual corrections, and judgment history. A failed grading request can resume from the saved case. |
| Mastery | Provisional confidence, time decay, partial recovery after help, independent recovery, and replacement of an old contribution after regrading. |
| Planning | Daily budget, ten-minute review candidates, progress-based refresh, visible deferred work, and recorded activity time. A missed activity gives no direct mastery penalty. |

The application runs locally with Bun, Vue, MongoDB, and sync-engine. Eight domain concepts and the stateless Generating adapter are assembled. Declared engine flows handle learning and planning. Reactions connect reviewed work, assessment, mastery, and plan refresh. Vue uses the generated client and result types. The host handles transport and file preparation.

## Limits and remaining work

Uploads are limited to 12 files and 25 MB combined. A source may contain up to 50 pages; a tutor request permits at most 40 page images. ZIP extraction is limited to 60 files and 50 MB expanded. Unsupported or oversized input produces an error. These limits are explicit; support for every file accepted by Codex or ChatGPT is not claimed.

P3 still needs graded-coursework import in the UI, exam management and explicit tradeoff confirmation, richer prerequisite and requirements editing, a source-search fallback, and deployment. New lesson/task requests can create another session after a lost response; saved sessions remain visible. Import and submitted-assessment recovery have durable identities. The single-process host locks are not a multi-server coordination scheme.
