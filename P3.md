## Updated journey

A learner opens StillGotIt and signs in with their 6.1040 Commons account. They create a course called Linear Algebra. On the course page, they drop in the lecture PDF on matrix multiplication. The app reads the file and shows the text it could read, so the learner can check it.

The learner asks for skills. The tutor reads the lecture and suggests a few skills, each with an outcome and a short description of how the learner will show it. The learner edits the wording, saves the drafts, and confirms one. It appears as a leaf on their skill tree.

The learner opens the leaf and sets a starting confidence. They ask for a worked example, and the tutor explains the skill from the lecture and cites the pages it used. Then the learner asks for a check of their understanding. The tutor gives two new problems and a why question. The learner answers in writing, by voice, or with a photo of their work. They review the whole attempt and send it.

The tutor assesses the work against the skill's requirements and explains its judgment. The leaf's mastery estimate changes, and the plan schedules the next short review. The learner sets a daily time budget and sees what to review today. When they come back later, their course, files, answers, judgments, and plan are still there.

## What changed since P2, and why

- **The app runs on the class platform.** The platform runs one Bun process on a read-only disk, with a single MongoDB server and S3 storage. The server now reads its address and origin from the platform, answers health checks, and saves uploads to S3.
- **Gemini replaced the ChatGPT connection.** The ChatGPT sign-in only worked on a local machine, so it could not run online. The app owner's Gemini key now powers every AI feature, including dictation. When the tutor fails, the learner sees why: the service is busy, the quota is used up, the answer was blocked, the request timed out, and so on.
- **File import moved to TypeScript.** The platform has no Python or LibreOffice. The importer now reads PDF text, images, text and code files, notebooks, and the text of Word, PowerPoint, and Excel files in the server process. ZIP and audio uploads are refused with a message.
- **Writes are safe without transactions.** The platform's MongoDB has no transactions. SkillMapping now writes records one at a time in an order that a retry can finish, as [runtime responsibilities](design/runtime.md#safe-writes-without-transactions) explains.
- **GroundedTutoring is simpler.** Following TA feedback on P1, two unused actions, `askFollowup` and `clarifyInput`, were removed. Their checks depended on judging what a question means, which code cannot check. Lessons and practice sessions are now listed in the order they were started.
- **Several courses.** A learner can create more than one course and switch between them from the course menu in the header. Each course keeps its own materials, skills, daily budget, and plan. Only one review can be in progress at a time, across all courses.
- **Interaction fixes.** Every disabled button says why it is disabled. Each view shows success and error messages, and server explanations reach the learner. Dates and source locations are readable ("Fri, Oct 23", "Lecture 4, page 1"). Keyboard focus returns to the control the learner used.
- **Visual design.** The new look comes from the [visual study](design/visual-design.md): Georgia headings, Avenir Next text, clear buttons, and one cyanotype blue. Course materials is now a library: the files, an "Add material" button with a drop area, and the skills grouped by topic. The chat screen follows the familiar layout of AI chat apps. The skill tree uses the line drawing from the sign-in page, and each skill's leaf shows its mastery as a shade of blue and a percentage. Today's plan is open on the home screen. A Settings button in the header holds the account and a note about the AI tutor. Each course sets its own daily study time from Today's plan.

## Tests

`bun run check` checks the concept sources, the generated files, and the types. `bun run test` runs every test file against a real, standalone MongoDB server. Each file uses its own database, and no test calls Gemini. The saved run is in [tests/output/p3-test-run.txt](tests/output/p3-test-run.txt).

The concept tests include an operational-principle test for each concept, variants such as retries, cancellations, and two learners acting at once, and refusals that also check nothing changed. HTTP tests cover the full journey with controlled AI answers, access by another learner, requests without a session, made-up IDs, and file downloads. Only the learner who uploaded a file can download it.

## Validation

- **Deployed app.** `/health` answers GET and HEAD. Requests without a session, from another origin, or with a made-up session are refused. Unknown pages return 404. The app owner signed in on the deployed app and used it.
- **Real Gemini, locally.** With `gemini-3.8-flash`, a local run of the journey worked end to end. It imported a PDF, suggested skills with specific requirements, gave a lesson with citations, created practice, and assessed the answer. Separate checks confirmed structured answers, PDFs sent whole, and Chrome dictation recordings.
- **Grading consistency.** The same correct answer was graded three times by each candidate model. `gemini-3.8-flash` judged it the same way every time and stayed below the time limit, so it is the default.
- **Interface.** In an isolated browser test with canned AI answers, sign-in, course creation, import, suggestions, confirming skills, the planner, a lesson, practice, assessment, and regrading all worked at desktop and phone widths, with keyboard focus checked after each action.

## Known limits

- A PDF made only of scanned pages has no readable text, so it cannot be imported on its own.
- GIF, BMP, and TIFF images are refused. Excel dates appear as serial numbers.
- Most planning and learning refusals reach the learner as "Check the field and try again" instead of the specific reason.
- Photos of the learner's own work are listed with the course materials.
- Asking for skill suggestions again replaces suggestions the learner edited, without a warning.
- A course cannot be renamed, and a learner cannot delete their uploaded files.
- Each course has its own daily budget, and nothing limits the total across courses.
- Skills are grouped by topic, but a skill does not yet show which file it came from.

## Plan for P4

- Graded-coursework import, exam deadlines with explicit tradeoffs, prerequisite editing, and a source-search fallback.
- Fix the limits above.
- Simplify the concepts further: move the material library out of GroundedTutoring, drop proposal receipts and requirement versions, compute plan totals instead of storing them, give the review schedule its own concept, and write each reaction as an explicit when/where/then.
